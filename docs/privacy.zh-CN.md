# 隐私说明

[English](./privacy.md)

本文说明自建 Peerto 时，数据分别由浏览器、Peerto 应用和网络辅助服务处理。

## 存储授权

Peerto 加载应用状态前，会要求用户授权一个必需的第一方 Cookie 和浏览器本机存储。不同意时应用保持不可用。Cookie 只保存当前授权版本（`peerto_storage_consent=v1`），使用 `SameSite=Strict`，一年后过期；它不用于广告、分析或跨站跟踪。

授权后，全新安装会先要求输入本机名称，再创建设备身份；已有安装继续使用已保存名称。PWA Service Worker 注册和离线缓存也只在授权后开始。浏览器会在同站请求中携带授权 Cookie，但应用服务器不会把它用于身份、信令或跟踪。

## 浏览器本地

当前浏览器会保存：

- 设备名称和稳定设备 ID
- P-256 设备私钥
- 已配对设备的公钥和恢复凭据
- 本地消息记录、文件名和传输状态
- 用户选择的 STUN 和 TURN 设置
- 文件句柄与 OPFS 中的资源内容
- 浏览器 Cache Storage 中的 PWA 应用文件

这些数据不会自动同步到其他浏览器。清除站点数据会删除身份、配对和本地历史，之后需要重新配对。

网络或心跳失败后，已认证连接可在内存中休眠保留 30 秒，供用户点击重试时探测上次路径。休眠期间不处理业务消息、不自动恢复在线，但浏览器底层 ICE consent 流量可能继续。远端地址不会作为重连缓存持久化；刷新页面或主动取消会关闭保留的传输。

如果填写 TURN 用户名和密码，它们只保存在当前浏览器。任何能读取该浏览器站点数据的人或扩展都可能取得这些信息，因此公共设备上不应保存私人 TURN 凭据。

## Peerto 应用服务器

应用服务器在建链期间会处理：

- 来源 IP
- 6 位连接码
- 设备名称、设备 ID 和公钥
- 短时随机凭据的哈希
- SDP 与 ICE Candidate
- WebSocket 状态

这些信息用于身份验证、限流和 WebRTC 建链。房间有短 TTL，双方 P2P 上线后立即删除可加入房间；已认证的 Socket 和最小运行状态最多再保留 30 秒用于连接稳定，随后释放。应用进程重启也会清空全部会合状态。

应用服务器不会接收或保存：

- 消息正文
- 文件内容
- P-256 私钥
- 浏览器本地历史
- 用户在设置页填写的 TURN 配置

日志配置会隐藏请求 URL，不记录连接码、令牌、SDP、ICE、消息和文件。运维人员仍应限制日志访问，并检查入口代理是否额外记录了完整查询参数。

## STUN

浏览器会向设置中的 STUN 服务发送 Binding 请求，用来发现公网映射地址。STUN 服务会看到请求来源 IP。默认列表包含第三方公共服务，运营者不能替这些服务承诺保留周期或隐私政策。

不希望访问公共 STUN 时，可以在设置页替换为自己的服务。

## TURN

只有 ICE 需要 relay 时，业务流量才经过 TURN。TURN 运营者可以看到两端 IP、连接时间和流量大小，但 WebRTC DataChannel 的 DTLS 加密仍保护消息与文件内容。

TURN 地址和凭据不会由 Peerto 应用服务器下发。它们由用户在当前浏览器设置。

## Cloudflare

使用 Cloudflare Tunnel、代理、WAF 或 Turnstile 时，Cloudflare 会处理到 Peerto Web 和 API 的请求，并可见来源 IP、请求路径和浏览器信息。具体处理方式受站点运营者的 Cloudflare 配置与政策约束。

Turnstile token 只用于创建连接码的人机验证。Peerto 服务端验证后不会保存 token。

## 删除

资源页可以单独删除或清空本机文件。删除会话会移除当前浏览器中的消息、资源和配对记录。对方在线时，可以选择要求对方先删除同一会话；对方确认成功后，本机才继续删除。

服务器端短时状态不能作为聊天记录恢复来源。它会自动过期，也没有提供导出接口。
